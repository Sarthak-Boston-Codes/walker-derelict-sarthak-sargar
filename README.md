# walker-derelict-sarthak-sargar

**DERELICT**: a top-down 3D zombie shooter in a derelict factory, built for CSYE 7270. Assignment 7 adds two HUD animations: a spinning keycard icon and a pistol reload rig.

## Start point
An empty Godot 4 project (Assignment 2). It was redone as a top-down 3D shooter on branch `a2-redo-3d` (tag `a2-redo`; see REDO-LOG.md). A5 added shaders and materials (tag `a5`), A6 added two particle effects (tag `a6`, branch `a6-effects`), and A7 builds on the top of `a6-effects` (commit 020fc24) on branch `a7-animation`. The original 2D slice still runs from `scenes/main.tscn`.

## Engine and renderer
Godot 4.7.2 (stable), GDScript. Renderer: Forward+ (the default; `project.godot` names no `rendering_method`), D3D12 on Windows. Physics: Jolt.

## Run instructions
- Play: open `godot/project.godot` in Godot 4.7.2 and press F5, or `godot --path godot`. The main scene is `res://game3d/menu.tscn`.
- Import first on a fresh clone: `godot --headless --path godot --import`.
- Tests (Git Bash, from the repo root; `GODOT` defaults to the local install; logs in `logs/`):
  ```
  bash scripts/run-test.sh game3d_smoke_test.tscn 60
  bash scripts/run-test.sh game3d_soak_test.tscn 60
  bash scripts/run-test.sh showcase_3d_test.tscn 60
  bash scripts/run-test.sh trigger_count_test.tscn 60
  bash scripts/run-test.sh low_ammo_test.gd 30      # and 60, 144
  bash scripts/run-test.sh test_materials.gd 60
  bash scripts/run-test.sh calibrate_normal_map_check.gd 60
  bash scripts/run-test.sh test_impact_burst_config.gd 60
  bash scripts/run-test.sh test_impact_burst_state.gd 60
  bash scripts/run-test.sh test_wound_smoke_config.gd 60
  bash scripts/run-test.sh test_wound_smoke_state.gd 60
  bash scripts/run-test.sh cost_effects.gd 60 300   # headless CPU price (A6)
  bash scripts/run-test.sh test_pins_player.gd 60
  bash scripts/run-test.sh test_keycard_spin_readback.gd 60
  bash scripts/run-test.sh test_pistol_reload_readback.gd 60
  bash scripts/run-test.sh test_hud_anim_structure.gd 60
  bash scripts/run-test.sh test_hud_anim_state.gd 60
  bash scripts/run-test.sh test_pistol_reload_edges.gd 60
  bash scripts/run-test.sh test_two_clocks.gd 60    # and 30
  ```
  `realtime` in place of the frame rate runs without `--fixed-fps` (none of the A6 or A7 tests needs it). The wrapper fails a run on SHADER ERROR, SCRIPT ERROR or Failed loading resource.
- GPU price (needs a window): `godot --path godot --resolution 1280x720 --script res://tools/gpu_price.gd`. The script turns vsync off itself. No F9 vsync toggle was added: F9 is unused, but an in-game key would be an input change the brief keeps out of scope.
- Frame strips (need a window): `godot --path godot res://previews/pistol_reload_preview.tscn --write-movie <abs path>/frame.png --fixed-fps 30 --quit-after 60` (also `pistol_reload_preview_light`, `keycard_spin_preview`, `keycard_spin_preview_dark`); readings in TUNING.md. A6's particle strips: `docs/archive/TUNING-a6.md`.

## Controls
WASD move · mouse aim (the flashlight follows) · hold left click to fire · R reload · F flashlight · Esc pause · M / N mute music / SFX.

## What Assignment 7 added
- **Keycard spin (the cycle)**, route 1: a `Sprite2D` `KeycardIcon` with an `AnimationPlayer` frame track (`godot/game3d/keycard_icon.tscn`, clip `godot/animations/keycard_spin.tres`). 8 cells of 64 × 64 from `godot/art/keycard_sheet.png`, generated by `tools/make_keycard_sheet.py`. 12 fps, discrete updates, `LOOP_LINEAR`. It appears beside "◆ KEYCARD" when the keycard is picked up and spins until the scene ends.
- **Pistol reload (the committing action)**, route 3: a `Node2D` cutout rig `PistolRig` (`Body`, `Slide`, `Mag` pivots with `Polygon2D` parts; `godot/game3d/pistol_rig.tscn`, clip `godot/animations/pistol_reload.tres` plus a `RESET` animation). 24 fps, `LOOP_NONE`, 1.25 s = `RELOAD_TIME`. Startup (tilt, magazine out) 0–0.5 s, active (magazine seated, slide racked) 0.5–1.0 s, recovery (gun levels) 1.0–1.25 s. It sits bottom-right of the HUD.
- **One authority:** `godot/game3d/hud_anim.gd` (`HudAnim`) is the only code that plays or stops either clip. Its state tables are HOLD / RELOAD / DEAD from `reload_changed` and `died`, and HIDDEN / SPINNING from the HUD keycard label. Both `AnimationPlayer`s are `PROCESS_IDLE`, `PAUSABLE` and have empty autoplay. `game.gd` gained 4 lines to attach it; `hud.gd` and `player.gd` are unchanged.
- Tests: pins taken before wiring and re-run after; read-backs of both clips; a structure test (tables, one writer, process modes); a state test through real key, mouse and zombie input; an edge test with interrupts at every phase boundary; a two-clocks measurement; four mutations.
- Specification: CHANGE-BRIEF.md (with dated revisions). Results: TEST-REPORT.md. Strips and tuning: TUNING.md, `captures/pistol_reload/`, `captures/keycard_spin/`. Run log: A7-LOG.md. Human checks: HUMAN-CHECK-NOTES.md.
- **Authorship:** the brief, its predictions, the phase table, the cycle spec and the approvals were written by Claude; the sheet generator, clips, rig, `HudAnim`, tests, pins, previews, captures, strip readings, documents and film were written by Claude Code. Per-file detail: SOURCES.md.

## Known limitations
- Every human check and every tuning verdict is pending: not yet performed by the student (HUMAN-CHECK-NOTES.md).
- The reload clip trails the game's reload timer by exactly one frame (it holds position 0 on the tick after `play()`); the RESET pose replaces its last frame. Fire unlocks on the game's own tick.
- The keycard icon is small (a 26 px card at 1280 × 720).
- The sheet's back face is on cells 3–5, not the brief's 4–7 (dated revision).
- A6's `test_impact_burst_state.gd` failed its two-hit section once, on the first run after a fresh import.
- From A6: impact-burst sizes do not change over life; the wound smoke reads lighter than its background when standing still; barrel-blast hits fire no burst. Earlier: see `docs/archive/`.

## Earlier assignments
### Assignment 6 (tag `a6`)
- **Effect A, impact burst** (`godot/effects/impact_burst.tscn`): three `GPUParticles3D` (Flash, Sparks, Puff) under one Node3D. It fires on every bullet that hits a zombie, barrel or crate. `player.gd` gained one signal, `bullet_hit(point, normal)`, and one emit line (the only gameplay edit). `godot/game3d/impact_fx.gd` keeps a pool of 12 bursts under the level root, so rapid hits overlap, a burst outlives the zombie it hit, and a full pool restarts the oldest.
- **Effect B, wound smoke** (`godot/effects/wound_smoke.tscn`): one `GPUParticles3D` at the player's chest with turbulence. `godot/game3d/wound_smoke_driver.gd` reads `health_changed` and writes only `emitting` and `amount_ratio` = clamp((60 − hp) / 50, 0.2, 1.0) while hp ≤ 60; it never writes `amount`.
- Configuration tests read every brief setting back from the scenes; state tests drive real fire, real zombie damage and a real medkit; Godot's generated particle process shader is saved in `godot/shaders/particles_generated.gdshader`.
